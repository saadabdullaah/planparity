# Known limitations

- PlanParity is not an operating-system sandbox. Provider plugins and data sources are third-party local code and may attempt network or filesystem access.
- `-refresh=false` avoids normal refresh behavior but does not prove that every provider action is offline.
- Known credential-like environment variables are removed, but this cannot guarantee that no credential exists in a file, helper, agent, platform service, or unrecognized variable.
- Registry/module initialization may need network access unless dependencies are already cached.
- Probable move detection is heuristic and remains `INFERRED`.
- A locally equivalent plan does not guarantee an equivalent production apply.
- Unsupported or malformed future engine JSON formats fail closed rather than being guessed.
- Report/API schema `planparity/v1` is stable for version 1, but pre-1.0 artifacts may not read reports generated by later builds.
- The UI is designed for desktop and compact browser widths, but it is not a hosted or multi-user application.
- Windows and Linux are supported. macOS is not a version-one target.
- Remote state backends, cloud accounts, apply/remediation, policy languages, CI product integration, and additional IaC engines are outside version-one scope.
- Very large graphs are expensive. Search/filter the resource inventory before relying on a complete topology view.

Treat `FAILED`, `UNSUPPORTED`, `UNVERIFIED`, and ambiguous results as unresolved evidence, not approval to proceed.
